Guide

From empty repo to agent-run board.

The whole workflow in one page: install, seed a board, hand tickets to coding agents, and keep every move audited. Commands are copied from the tested README.

Matches Atlas Tasker v1.9+ · Full docs live in the repository

1 · Install

curl -fsSL https://raw.githubusercontent.com/myrrazor/atlas-tasker/main/scripts/install.sh | sh

The installer fetches the latest release, checks its SHA-256 checksum, verifies the GitHub build attestation, and installs tracker. Building from source works too: go install github.com/myrrazor/atlas-tasker/cmd/tracker@latest.

2 · Minutes to a working board

tracker init — sets up the workspace in your repo.

tracker project create APP "My App" — projects group tickets and get their own board.

tracker ticket create --project APP --title "Ship first feature" --type task --actor human:owner --reason "first ticket" — every write names an actor and a reason; that pair is the audit trail agents and reviewers read later.

tracker ticket move APP-1 ready --actor human:owner --reason "groomed" then tracker board — the board in your terminal. tracker tui opens the full-screen view; tracker web serve opens the local Kanban with the welcome dashboard.

3 · Hand work to agents

tracker agent create builder-1 --name "Builder" --provider claude --capability go registers an agent; tracker ticket assign APP-2 agent:builder-1 --actor human:owner --reason "agent work" hands a ticket over. Dependencies: tracker ticket link APP-2 --blocked-by APP-1 ….

tracker team apply crossfire --actor human:owner --reason "agentic loop" installs a ready-made team preset — profiles, runbook, separation-of-duties permissions, and the completion gate in one idempotent command.

tracker integrations install codex / tracker integrations install claude teach your coding agents the loop; tracker mcp serve exposes typed tools for MCP-capable agents.

4 · Keep it honest

Statuses move backlog → ready → in progress → in review → done, with blocked as the exception lane. Approval gates, evidence, and comments live on the ticket; the web board's drawer shows Notes & activity, Policy/Gates, and Evidence tabs. Everything is Markdown + an append-only event log in your repo — the SQLite index is disposable and rebuildable with tracker doctor --repair.

- `tracker integrations detect` and interactive `tracker integrations install` discover local coding agents and let you checkbox-select which integrations to write; `tracker init --integrations` / `--skip-integrations` control the post-init prompt.
- Added `tracker update` for production self-updates: check/dry-run/apply against GitHub releases with checksum verification, optional `gh attestation verify`, and atomic binary replace.
- MCP workflow profile covers the real agent loop: ticket create/assign/link/unlink/approve/reject/complete, agent create/edit/enable/disable, team apply, goal brief, and wake-up list/view/ack. `atlas.ticket.complete` is a normal workflow write (no operation-approval token); provider merge/sync/archive tools stay high-impact.
- MCP stdio accepts both newline-delimited JSON-RPC and LSP-style `Content-Length` frames.
- Same-status `ticket move` is a no-op across CLI, MCP, and bulk (matching the web board). Bulk operations with per-ticket failures exit non-zero (conflict → 4) while still printing the result envelope on stdout.
- `tracker init` refuses nested workspaces under an existing root, and a plain re-init prints `already bootstrapped`.
- `ticket show` aliases `ticket view`; unknown ticket/agent/bulk/integrations/mcp subcommands exit 2. `--type` is required on create unless a template supplies it. `ticket create` and `ticket move` resolve `--actor` the same way claim does (no silent `human:owner` flag default).
- Open completion mode can `ticket complete` from `in_progress` without the three-step request-review → approve → complete path.
- `integrations install` gains `cursor` and `grok` targets, writes generic/cursor/grok blocks into root `AGENTS.md`, and supports `openclaw --global` for `~/.openclaw/skills`.
- Docs honesty: KNOWN_LIMITATIONS #100, installation/getting-started RC wording, AGENTS.md actor/same-column notes, and MCP one-liner framing warnings.

## v1.10.0 - Local Web UI And Agent-Ready CLI (2026-09-08)

Hosted RC checks, artifact attestations, clean installation, packaged smoke, and the owner stable decision are recorded in [v1.10 release evidence](docs/release/v1.10.0-release-evidence.md).

- Transactional index recovery, consistent workspace guards, webhook JSON redaction, installer symlink rejection, loopback listener validation, and assignment-aware promotion recommendations.

- The SQLite index now rebuilds itself when it is missing or stale. Every workspace open compares a fingerprint stamped into the index (event-log lines, ticket files) with the sources on disk and, on a mismatch, rebuilds under the write lock before answering — `board`, `ticket view`, the TUI, `web serve`, and `mcp serve` alike. A deleted `index.sqlite` used to print an empty board with exit 0, looking exactly like data loss. The rebuild announces itself once on stderr (`[tracker] index.sqlite was missing or stale; rebuilt it from markdown and events (events=13 tickets=5)`); the next command is quiet, an empty workspace stays silent, and a workspace upgraded from a release without the stamp rebuilds exactly once.
- `tracker doctor` stops blessing a stale index. It compares the stamped fingerprint with the sources and reports drift as `repair_needed` (exit 7) with both fingerprints in the message, instead of `doctor ok` computed from the markdown alone. `doctor --json` (with or without `--repair`) gains an `index` object (`stale_before_repair`, `rebuilt`, `stored_fingerprint`, `current_fingerprint`). A byte-corrupt index still stops every command with exit 7, but `tracker reindex` now recovers it instead of failing with the same exit 7 it was meant to fix, and `mcp serve` maps that case to `repair_needed` rather than leaking the raw sqlite error.
- Atlas has a local browser UI. `tracker web serve` starts a loopback-only server with a welcome dashboard at `/`, the Kanban board at `/board`, a schedule workspace at `/schedule`, and a read-only settings page at `/settings`. `tracker web open` reopens the last recorded URL and fails fast when that server is down, `tracker web status` reports it, `--read-only` disables every web mutation, and the runtime state file is removed on shutdown. Everything is server-rendered through the same `QueryService`/`ActionService` paths as the CLI — no hosted mode, no login system, no second database, no external requests.
- The web UI is restyled to the atlas.pen visual system: same layout — topbar, filter row, six workflow columns, right-hand ticket drawer — with a new skin. Deep-navy surface tokens from the pen spec (#0B0F14 background, #68A9FF accent, semantic status hues), vendored Geist and Geist Mono variable fonts (Inter dropped), mono ticket keys and counts, column accent bars, and tinted status, priority, and schedule-state pills. Semantic color stays on compact indicators, so the colored left card borders are gone. Drag-and-drop, drawer motion, reduced-motion behaviour, and the responsive breakpoints are untouched, and board and drawer controls keep 44px touch targets on phones.
- The welcome page gives cross-project orientation before card-level work: a borderless project ledger with real counts, a recent-change rail, and guarded project creation behind the same origin/CSRF/read-only gates as everything else. Web identity falls back from `web.owner_name` to `actor.default` to the OS username.
- Web sessions are deliberately boring: a random per-process token in a strict same-site cookie scoped to the server's port (so two workspaces can be served at once), origin and CSRF checks on every mutation, a strict CSP, and no CORS.
- BREAKING: `--unsafe-host` is gone. `tracker web serve` now rejects any non-loopback host outright — the board has no remote identity, authorization, or TLS story, and a warning does not contain exposure on an untrusted network.
- The board and welcome chrome speak six languages: English, Spanish, Indonesian, Chinese, Japanese, and Korean. Resolution is `?lang=`, then `web.lang`, then `Accept-Language`, then English; ticket titles, comments, labels, actors, and audit reasons stay exactly as stored. Two honest gaps: `tracker config set web.lang` still validates only `en`, `es`, and `id` — reach `zh`/`ja`/`ko` through the in-page language switcher or `Accept-Language` for now — and the schedule workspace is English-only.
- Tickets can carry a one-time schedule. `tracker schedule set <ID> --at <RFC3339> --runner <actor>` makes the runner the assignee so scheduling and workflow ownership cannot drift; `schedule list` and `schedule history` report what is pending and what completed; `schedule clear` removes the schedule without touching the assignee. `schedule tick` triggers everything due: a human runner gets a reminder through the existing notification sinks, an agent runner gets an Atlas wakeup, and command-mode agents launch their configured worker. Tick is a deliberate one-shot so cron, launchd, or whatever already owns cadence on your machine controls it — Atlas does not grow a daemon. Terminal tickets cannot be scheduled, and agent schedules are `human:owner`-only because they can start a local process.
- The `/schedule` workspace shows the same schedules as a week strip and day timeline, with set, clear, and run-due-now available as native forms.
- MCP gains `atlas.schedule.list`, `atlas.schedule.history`, `atlas.schedule.set`, and `atlas.schedule.clear`. Tick stays CLI-only on purpose: execution cadence belongs to the owner's scheduler, not to a connected agent.
- `--json` now works on every command the agent skill tells agents to run. `ticket create/edit/archive/assign/priority/label add/label remove/link/unlink/comment/claim/release/heartbeat` all printed through the versioned envelope already but never registered the flag, so `--json` came back as an unknown flag. `project create`, both `policy set` commands, `reindex`, and `config get/set` picked it up too, and a test walks the command tree so the next command that forgets it fails the build. Five surfaces stay out by design: `mcp serve` (owns stdout for JSON-RPC), `shell`, `tui`, `web serve`, and `web open`.
- `tracker init --json` reports the canonical workspace root and the scaffolding it laid down. Re-running reports an empty `created` list, which is how a script tells "already bootstrapped" from "just bootstrapped".
- BREAKING: `tracker board --json` returns `columns`, not `Columns` — the only PascalCase key left in the JSON contract.
- Forbidden workflow transitions are conflicts now: exit code 4 in the CLI (previously 1) and HTTP 409 on the web, for single and bulk operations alike. Dropping a card on its current column is a no-op instead of a "forbidden transition: ready -> ready" error.
- Behavior change: running tracker in a directory that never went through `tracker init` is exit 2 now, instead of silently scaffolding a stray `.tracker` and reporting an empty-but-"healthy" board. From a subdirectory of a real workspace the error names the root to run from, and a refused read leaves nothing behind. `doctor` gets the same guard — it used to bless the stray directory it had just created. Only `init` and `integrations install` create a workspace.
- `invalid status` errors finally say what the legal values are — `(valid: backlog, ready, in_progress, in_review, blocked, done, canceled)` — everywhere a status is typed: `ticket create`/`ticket move`, `bulk move`, the TUI dialogs and slash commands, and the web board. The `--status` flag help on `ticket create` and `ticket list` enumerates them too, matching what invalid ticket types already did.
- `tracker --help` teaches the happy path instead of opening on an alphabetical wall of ~70 commands: the root help now explains what Atlas is and walks `init` → `project create` → `ticket create` → `board`.
- When the last blocker of an agent-assigned ticket reaches `done`, Atlas now moves the dependent from `backlog` to `ready` itself before waking the agent. The move is an ordinary `ticket.moved` by the system actor `agent:atlas` with the reason `unblocked: APP-1 completed by human:owner`, chained to the completion by correlation and causation ids. Before this the wakeup fired — `agent.work_available` event, notifier line and all — but `tracker next`, `agent available`, and `queue` came back empty for the woken agent, because the ticket the wakeup pointed at was still in `backlog` and no query showed it. Promotion is best-effort: if it fails, the completion still succeeds and the wakeup lands with `promoted: "false"` and a `promotion_error` in its metadata (a move that died after its canonical write leaves the wakeup `failed` and pointing at `tracker doctor --repair`, which replays it). A ticket someone set to `blocked` by hand is woken but not moved.
- Queues show unblocked backlog. `tracker queue` and `tracker next` gain an `unblocked_for_me` category — backlog tickets whose blockers are all `done`, ordered right after `ready_for_me` — and `agent available` lists the ones an agent may act on (its own, or unassigned and claimable) with action `promote` and the `ticket move <ID> ready` as the first suggested command (`backlog -> in_progress` is not an edge). This is how human-assigned and unassigned dependents surface, since only agent-assigned ones are promoted automatically; a human-assigned one shows only in that human's `queue`/`next`. Backlog that never had blockers is untouched and still reports `not_ready_status`.
- A write that dies between its canonical file and the event log no longer loses its mutation journal to the next write. The event never landed, so the next write draws the same event id and used to overwrite the journal entry, leaving canonical, event log, and projection disagreeing while `doctor` reported nothing pending. `journal.Begin` now refuses a pending entry with `repair_needed` and `run 'tracker doctor --repair'`, which replays the stranded event.
- `tracker mcp serve --workspace <path>` pins the server to a repo. User-scoped registrations (`claude mcp add --scope user`, a global Codex `mcp_servers` entry) start the server wherever the client happens to be, which showed up as `not_found` for tickets sitting right there in the terminal. The path is checked before serving: missing is `not_found`, present but un-initialized says to run `tracker init` there.
- Added `tracker integrations install openclaw`. The `atlas-worker` skill lands in `.agents/skills/`, OpenClaw's repo-local skill root, and `AGENTS.md` gets its own marker pair so the codex and openclaw blocks stop overwriting each other. The shared `~/.openclaw/skills` copy stays a manual step; the generated guide has the one-liner. The skill gates itself on the `tracker` binary through OpenClaw's `requires.bins` metadata.
- Fixed skill frontmatter that never parsed: the generated `description` contained a bare `": "`, which is not a legal plain YAML scalar, so the `atlas-worker` skill's frontmatter was unreadable for every target. Descriptions now lead with the phrases that should activate them, and a test parses what we generate.
- Rewrote the root `AGENTS.md` for agents *using* Atlas instead of building it — don'ts first (writes need `--actor` and `--reason`, `project create` takes neither, a forbidden transition is a deliberate exit 4, the browser board is human-only), then the loop with real `--json` output, the status-edge table, and exit codes 0..7. `CLAUDE.md` imports it. The old v1 contributor guide moved to `docs/v1-agents-archive.md`.
- Exports, backups, audit artifacts, and goal artifacts now fail closed on symlinked inputs. Following a link could copy files from outside the workspace into a shareable artifact, and silently skipping it would produce an incomplete artifact without saying so, so the operation errors before anything is written.
- The build supply chain is pinned: every third-party GitHub Action in the CI and release workflows references a reviewed commit, those workflows run with `contents: read` and only the publish job elevates the three permissions it needs, an executable policy check keeps both true, and `govulncheck` now runs weekly in CI.
- Go moved to 1.26.6 and the reachable vulnerable modules (the Markdown and text renderers) to their first fixed versions; CI and release jobs are required to use the same runtime as `go.mod`.
- Added a static marketing site under `site/`: landing page, a first-board walkthrough, CLI and MCP reference pages, a docs section, a changelog page, privacy and terms, `llms.txt`, `robots.txt`, a sitemap, `security.txt` — and intentionally no analytics.
- README: added the `go install` line, a web board section with screenshots, and pointed the agents section at `AGENTS.md`. Fresh web screenshots (board and schedule at desktop and phone widths, plus the welcome dashboard) live in `docs/assets/`.
- Smaller web fixes along the way: rejected form posts re-render the board in place with the real error and everything the user typed echoed back, saved views respect the project/assignee/type filters, and `--open` works on Windows.

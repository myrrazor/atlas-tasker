## Sprint 114.3 — managed agent experience and board presentation

### AT114-301 — Managed-mode policy implementation

**Implementation**

Persist the workspace-shared policy separately from local provider state.

Required policies:

```text
capture:
  never
  ask
  material_work

progress:
  none
  milestones
  every_checkpoint

status:
  atlas_required

completion:
  follow_workspace_policy
```

Default recommended mode:

```text
capture = material_work
progress = milestones
status = atlas_required
completion = follow_workspace_policy
```

**Acceptance**

- Status queries never create tickets.
- Read-only questions never create tickets.
- Material repository changes are attached to an existing or new ticket.
- Dependency- or policy-blocked work is not started.
- Completion honors the existing workspace completion mode.
- User instruction can disable tracking for a particular task.

### AT114-302 — Expand the existing atlas-worker skill

**Implementation**

Update the shared skill generator and provider blocks.

The skill must instruct the agent to:

- Use MCP first.
- Call `atlas.context` when starting material work.
- Search before creating a ticket.
- Use the ticket named by the user.
- Avoid duplicate work.
- Claim before substantial edits.
- Move to active status only through a legal workflow edge.
- Record milestone progress, not every command.
- Add durable evidence for tests and reviews.
- Request review or complete according to policy.
- Query Atlas before every status report.
- Reconcile Atlas state before final completion messaging.

**Acceptance**

- No duplicate skill introduced.
- All six generated variants contain the same core lifecycle.
- Provider-specific instructions use that provider's configured identity.
- Reinstall updates the managed version without replacing user rules.
- Skill describes MCP fallback accurately.

### AT114-303 — Add `atlas.context`

**Implementation**

Create a read-only MCP tool returning:

- Workspace identity.
- Current project inventory.
- Configured Atlas actor for this integration.
- Managed-mode policy.
- Completion/review policy.
- Assigned active tickets.
- Available work.
- Pending blockers.
- Active runs.
- Current backup health.
- Current state revision and generated timestamp.

Arguments may include:

```json
{
  "project": "APP",
  "actor": "agent:builder-1"
}
```

**Acceptance**

- Bounded output.
- Pagination metadata.
- No credentials.
- No absolute private path unless explicitly requested through an authorized diagnostic profile.
- No mutation.
- Exact current state, not conversational memory.
- Missing configured actor is a visible setup error.

### AT114-304 — Add `atlas.status`

**Implementation**

Provide scopes:

```text
workspace
project
ticket
agent
run
```

Project status returns:

- Counts by status.
- Ready work.
- In progress.
- Blocked with stable reason codes.
- In review.
- Recently completed.
- Assigned agents.
- Recent significant changes.
- Recommended next actions.
- Backup health summary.
- Board URL when available.

Return both:

- Structured JSON/`structuredContent`.
- Deterministic compact Markdown.

**Acceptance**

- "Status of APP" cannot accidentally return another project.
- Unknown project produces disambiguation.
- Multiple projects return workspace overview unless one was named.
- Large boards paginate.
- Generated Markdown is derived entirely from structured data.
- Agent cannot invent progress percentages not represented in Atlas.

### AT114-305 — Board renderer and progressive MCP App

**Implementation**

Create a read-only board presentation shared by:

- MCP Markdown responses.
- Optional MCP App UI.
- Existing web board linking.

The MCP App is progressive enhancement:

- Hosts with MCP App support render the compact board.
- Other hosts receive Markdown.
- The same structured payload backs both.
- No mutation controls in the first MCP App version.
- No third-party scripts.
- No credentials.
- No terminal or source-code access.

Cursor officially supports MCP Apps, but the universal fallback must remain fully functional for
every target. (Verified; a known project-scope widget limitation is recorded in the capability
matrix.)

**Acceptance**

- Project-specific board.
- Accessible columns and cards.
- Bounded number of cards.
- Truncation and pagination indicated.
- Blocked/review states clear without color alone.
- App cannot invoke write tools.
- Content Security Policy test passes.

### AT114-306 — Managed workflow and natural-language end-to-end evaluation

**Scenarios**

For each named provider:

- "Use Atlas Tasker to manage this project."
- "What is the current status?"
- "Show the board for APP."
- "Pick up the next ready ticket."
- "Implement this feature."
- "I'm blocked on the API decision."
- "Give me an update."
- "Send this for review."
- "What should happen next?"
- "Hand this off to Claude."

**Required behavior**

- Fresh Atlas reads.
- Correct project resolution.
- Correct actor.
- No duplicate ticket.
- Legal status transitions.
- Proper blocker recording.
- Progress comments only at meaningful milestones.
- Test evidence attached.
- Review policy followed.
- Board reflects updated state.
- No high-impact Atlas operation invoked.
- No low-level commands exposed as required user actions.

### Sprint 114.3 gate

All six integrations must pass generated-skill inspection. Codex, Claude, Cursor, OpenClaw, and
Grok require real-client natural-language tests. Generic uses the conformance host plus one
representative generic MCP client.

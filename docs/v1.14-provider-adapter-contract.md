# v1.14 Provider Adapter Contract and Capability Matrix (AT114-003)

Status: Sprint 114.0 contract artifact, frozen for independent design review. The Go contract lives
in `internal/integrations/adapter`; this document explains it, records the verified provider
facts behind the capability matrix, and lists what remains unverified until Sprint 114.2 runs real
clients. No provider adapter is implemented yet; Sprint 114.2 (AT114-203..208) implements one
adapter per target against this contract without changing it.

Related: [v1.14 implementation plan](v1.14-implementation-plan.md) (AT114-003, AT114-201,
AT114-208, locked decisions 2–5), [unified setup ADR](v1.14-setup-transaction-model.md),
decision log entries DEC-071 and DEC-072 in [v1-decision-log.md](v1-decision-log.md).

## 1. Scope and non-goals

The contract fixes:

- one interface every target implements (`AgentIntegrationAdapter`);
- the nine reportable integration states from locked decision 5;
- the canonical Atlas MCP registration (locked decision 3, AT114-201) and how it is bound to one
  workspace (locked decision 4);
- a structured command model that makes shell interpolation impossible;
- a plan/apply/verify/repair/remove data model with fail-closed validation;
- the six-target capability matrix with the official source of every claim.

It does not implement detection, file editing, TOML/JSON merging, client CLI execution, the
setup journal, or the workspace registry. Those are Sprint 114.1 and 114.2 tickets.

## 2. Interface

```go
type AgentIntegrationAdapter interface {
    Target() integrations.Target
    Capabilities() Capabilities
    Detect(ctx context.Context, input DetectInput) Detection
    Plan(ctx context.Context, input PlanInput) (IntegrationPlan, error)
    Apply(ctx context.Context, plan IntegrationPlan) (ApplyResult, error)
    Verify(ctx context.Context, state IntegrationState) (Verification, error)
    Repair(ctx context.Context, state IntegrationState) (RepairPlan, error)
    Remove(ctx context.Context, state IntegrationState) (RemovalPlan, error)
}
```

`Target()` and `Capabilities()` are additions to the plan's six-method sketch. They let the
setup engine and the `Registry` check an adapter against the frozen matrix instead of trusting
it: `Registry.Register` rejects an adapter whose target is unknown, duplicated, or whose
capabilities disagree with `Matrix()` on `MaxPlannedState` or `PreferredScope`.

Method contract:

| Method | Writes | Runs client binary | Returns |
| --- | --- | --- | --- |
| `Detect` | never | only through `DetectInput.Runner`, only `detect_version`/`inspect` purposes | `Detection` (validated: installed ⇒ absolute executable; `supported` ⇒ parsed version; probes read-only) |
| `Plan` | never | never | `IntegrationPlan` with `Operation = setup` |
| `Apply` | only the plan's steps, in order, under the setup journal | only `Command` values carried by plan steps | `ApplyResult`; may report `pending_*`, `configured_unverified`, `portable_ready`, or `failed`, never `connected` |
| `Verify` | never | read-only probes | `Verification`; the only method allowed to produce `connected` / `connected_restart_required` |
| `Repair` | never | never | `RepairPlan` (`Operation = repair`) |
| `Remove` | never | never | `RemovalPlan` (`Operation = remove`) |

Only `Apply` mutates, and only what a validated plan says. This is what makes the AT114-002
transaction model enforceable: the engine snapshots each `PlanStep.Path` before `Apply`, runs
the step, and uses the step's `Rollback` on failure.

## 3. State vocabulary

`adapter.State` is exactly the nine strings of locked decision 5:

| State | Meaning | `Verified()` | `RequiresHumanAction()` |
| --- | --- | --- | --- |
| `connected` | Registration proven by a passed probe or client-native check | yes | no |
| `connected_restart_required` | Proven, but the client process must restart/reload before it sees the server | yes | yes |
| `pending_workspace_trust` | Config is in place; the client's workspace trust dialog is outstanding | no | yes |
| `pending_mcp_approval` | Config is in place; the client's per-server approval or admin policy is outstanding | no | yes |
| `configured_unverified` | Config is in place; no verification method could run (client absent, probe unavailable) | no | no |
| `portable_ready` | A portable descriptor and skill exist; no client is bound | no | no |
| `unsupported_client_version` | Client found but version unknown/unsupported; Atlas wrote no client configuration | no | yes |
| `repair_required` | Recorded state and disk disagree (moved workspace, changed entry, stale skill) | no | yes |
| `failed` | Apply or verify failed; rolled back | no | yes |

Rules enforced by `Validate()` on the plan and result types:

- `Apply` can never return a verified state; only `Verify` can (`ApplyResult.Validate`).
- A verified `Verification` needs at least one passed check whose method is not
  `manual_client_check`, plus a `ConnectionKind`.
- A plan with `ApprovalSteps` may only end in a pending state; a plan for an unsupported version
  may only end in `unsupported_client_version` and may not carry client-config steps; a plan for an
  uninstalled client may not end verified.
- Each target has a `MaxPlannedState` (`stateAtMost`): generic caps at `portable_ready`, OpenClaw at
  `connected_restart_required`, the other four at `connected`.

### 3.1 AT114-208 state names

AT114-208 lists `connected_by_standard_config` and `connected_by_custom_adapter` for the generic
target while locked decision 5 fixes nine states. The contract keeps the nine states and models
the AT114-208 distinction as `Verification.ConnectionKind`:

| `ConnectionKind` | Used by |
| --- | --- |
| `client_native` | Codex, Claude Code, OpenClaw, Grok when the client's own CLI proved the server |
| `self_probe` | Any named client verified only by Atlas starting the exact registered command |
| `standard_config` | Generic, after a managed `.mcp.json` entry passed the conformance host |
| `custom_adapter` | Generic, after a user-selected config destination passed the conformance host |

`Verification.Validate` requires a generic verified result to carry `standard_config` or
`custom_adapter`. This is recorded as DEC-071 and flagged for design review; if review prefers
eleven states, only `state.go`, this section, and the plan text change.

## 4. Canonical registration (AT114-201, locked decisions 3 and 4)

`MCPRegistration` is provider-neutral. Adapters render it into their client's native form; they
never assemble argv by hand.

```text
server_name   atlas-<first 12 hex of sha256(workspace UUID)>      pattern ^atlas-[0-9a-f]{12}$
transport     stdio
command       absolute tracker path | "tracker" (portable only)
args          mcp serve <binding> --expected-workspace-id <UUID>
              --tool-profile workflow --max-items 30 --max-result-bytes 65536
actor_hint    optional contracts.Actor (agent:<id>)
```

`RegistrationArgs` is the single derivation; `MCPRegistration.Validate` rejects any `Args` that
differ from it, any occurrence of `--dangerously-allow-high-impact-tools`, `--init-if-missing`,
or `--read-only`, any profile other than `workflow`, and any bounds other than 30 / 65536.

### 4.1 Workspace binding

| `WorkspaceBinding.Kind` | argv | Allowed scopes | Rationale |
| --- | --- | --- | --- |
| `absolute_path` | `--workspace /canonical/root` | `project_local`, `user`, `gateway` (machine-local files only) | Plan AT114-102: "use absolute --workspace where the provider supports a reliable local-project registration" |
| `client_variable` | `--workspace ${workspaceFolder}` (Cursor), `--workspace ${CLAUDE_PROJECT_DIR:-.}` (Claude `.mcp.json`) | `project_shared` | The client expands the variable; the server still checks the expected ID |
| `verified_cwd` | `--workspace-from-cwd` | `project_shared` (`.codex/config.toml`, `.grok/config.toml`, `.mcp.json`, portable descriptor) | Repository-carried files must not embed a machine path |

Every binding carries `--expected-workspace-id <UUID>`. This is stronger than the plan's minimum
("absolute path **or** verified cwd plus expected ID") on purpose: a moved, copied, or replaced
workspace at a still-valid absolute path must fail closed rather than answer for the wrong data.
`--workspace-from-cwd` and `--expected-workspace-id` do not exist in v1.13.0's `tracker mcp serve`;
AT114-102 adds them with the security rules listed in the plan. Until then a canonical
registration cannot be started by the real binary, which is why Sprint 114.2 depends on AT114-102.

`ValidateForScope(scope, home)` adds the repository-carried rules: a `project_shared`
registration may not use `absolute_path` and may not name an executable under the user's home
directory unless it is the portable bare `tracker`. Portable registrations must use
`verified_cwd`.

### 4.2 Rendered forms

`StandardConfigJSON()` renders the `mcpServers` shape shared by Cursor, Claude `.mcp.json`, and the
generic descriptor, always with `"type": "stdio"` (Cursor requires `type` for STDIO servers;
Claude Code accepts it). TOML rendering for Codex and Grok is an adapter concern in Sprint 114.2.
`Fingerprint()` is the SHA-256 of the registration's canonical JSON and is what `IntegrationState`
and `ExistingServer` record so removal can prove ownership byte-for-byte.

### 4.3 Deliberately absent

- No `env` in the registration. Atlas needs none, and `Command.Validate` refuses secret-looking
  environment names anyway.
- No project name, path, or raw workspace ID in the server name.
- No `delivery`/`admin` profile, no permanent approvals, no high-impact flag.

## 5. Command model (no shell interpolation)

`Command{Purpose, Executable, Args, Dir, Env, Timeout}` is the only way an adapter runs a client
binary. `Validate()` rejects:

- a relative, unclean, or empty executable, or one whose base name is a shell interpreter
  (`sh`, `bash`, `zsh`, `dash`, `ksh`, `fish`, `csh`, `tcsh`, `ash`, `cmd`, `powershell`, `pwsh`);
- NUL bytes anywhere, or a `scheme://user@host` credential URL in any argument;
- a non-absolute `Dir`, invalid or duplicate environment names, or environment names containing
  `TOKEN`, `SECRET`, `PASSWORD`, `PASSWD`, `API_KEY`, `APIKEY`, `PRIVATE_KEY`, `CREDENTIAL`;
- a timeout of zero or above ten minutes.

`Display()` quotes every argv element separately (never joins into a shell string).
`CommandPurpose.Mutates()` is true only for `register`, `reload`, `remove`; `Detect` and `Verify`
probes must be non-mutating and `PlanStep.Writes()` treats a read-only command step as a
non-write, which is what allows a plan to be `NoOp` while still re-inspecting the client.

## 6. Plan model

`IntegrationPlan` is deterministic (`Fingerprint()` excludes `PlanID` and `GeneratedAt`) and is the
unit AT114-002's journal applies. Validation rules that matter for review:

- **Containment.** Every file step path is inside the workspace (never the root itself) or inside a
  `ConsentedRoots` entry; `record_local_state` paths are inside `LocalStateRoot`, which must be
  absolute and outside the workspace, with mode `0600`.
- **Reversibility.** Every write is `reversible` with a `Rollback` (`restore_snapshot`,
  `delete_created`, or `run_command` with a validated `Command`) or `irreversible` with an
  `IrreversibleReason`.
- **Unsupported versions.** No step whose kind `TouchesClientConfig()` (`write_config_entry`,
  `remove_config_entry`, `run_client_command`) may appear.
- **Approvals.** `ApprovalStep` is reported, never executed; its `Requirement.PendingState()` is the
  only state the plan may promise.
- **Removal.** `Operation = remove` plans carry no registration, no approval steps, no resulting
  state, and only removal-class steps; `RemovalPlan` with unverified ownership must set
  `RequiresConfirmation`.
- **Secrets.** Step descriptions and warnings may not contain credential URLs.
- **NoOp.** A `NoOp` plan has no writing steps, and a plan with no writing steps must be `NoOp`
  (except `unsupported_client_version` and `failed` results).

default; alternatives require an explicit choice (locked decision 4). Facts marked (V) were verified
against the cited official documentation on 2026-09-10; anything else is in the "unverified" list
and must be confirmed by a real client run in Sprint 114.2 before an adapter reports `connected`.

(`client_variable`, workspace trust then MCP approval) and `user`; Codex `user` `~/.codex/config.toml`

All four named-client user scopes are never selected by default because they expose one workspace
to every project on the machine.

### 7.1 Per-provider verified facts and consequences

**Claude Code** — source: <https://code.claude.com/docs/en/mcp>.

- Scopes `local` (default, stored per project path in `~/.claude.json`), `project` (`.mcp.json`),
  `user`; precedence local > project > user, no field merging. (V)
- Project-scoped servers show `⏸ Pending approval` until the workspace is trusted and the server is
  approved; `disabledMcpjsonServers` rejects; `claude mcp reset-project-choices` clears decisions;
  `claude -p`/SDK sessions load project servers without prompting. (V)
- `claude mcp add` with an existing name at the same scope fails ("already exists"): `Apply` must
  branch on `Detection.ExistingServers`, never retry. (V)
- `${CLAUDE_PROJECT_DIR:-.}` is the documented placeholder for project-relative commands in
  `.mcp.json`; a typeless entry is stdio and `"type": "stdio"` is accepted. (V)
- Reserved server names: `workspace`, `claude-in-chrome`, `computer-use`, `Claude Preview`,
  `Claude Browser`; `atlas-<hex>` cannot collide. (V)
- Consequence: preferred `project_local` needs no approval and takes an absolute path; the shared
  `.mcp.json` option is explicit and ends in `pending_workspace_trust` until the human acts.

**Codex** — sources: <https://learn.chatgpt.com/docs/extend/mcp>,
<https://learn.chatgpt.com/docs/config-reference>.

- `~/.codex/config.toml` (`$CODEX_HOME`) is the user layer; `.codex/config.toml` is a project-scoped
  override loaded only for projects marked trusted via `projects.<path>.trust_level`. (V)
- Documented `[mcp_servers.<name>]` keys: `command`, `args`, `env`, `env_vars`, `cwd`, `required`
  (default false), `enabled`, `startup_timeout_sec` (10 s), `tool_timeout_sec` (60 s),
  `enabled_tools`/`disabled_tools`, `default_tools_approval_mode` (`auto | prompt | writes |
  approve`). (V)
- `codex mcp add <name> -- <cmd...>`, `codex mcp list`, `codex mcp get`, `codex mcp remove` exist;
  the CLI writes the user-level file, so the project table is an Atlas TOML edit. (V for
  existence; write location corroborated by third-party sources only, see unverified)
- Consequence: preferred scope is the repository-carried project file with `required = false`,
  binding `verified_cwd`, resulting state `pending_workspace_trust` until the project is trusted.

**Cursor** — source: <https://cursor.com/docs/context/mcp>.

- `.cursor/mcp.json` (project) and `~/.cursor/mcp.json` (global); STDIO entries need `type`,
  `command`, optional `args`, `env`, `envFile`. (V)
- Variables `${env:NAME}`, `${userHome}`, `${workspaceFolder}`, `${workspaceFolderBasename}`,
  `${pathSeparator}`/`${/}` are interpolated in `command`, `args`, `env`, `url`, `headers`;
  `${workspaceFolder}` is the folder containing the `.cursor/mcp.json`. (V)
- MCP Apps are supported with fallback to normal responses; per-call tool approval; enterprise
  MCP allowlists; custom servers need a restart after updates. (V)
- Consequence: `client_variable` binding, `Restart = unverified`, `MCPApps = supported`; AT114-305
  keeps Markdown primary because project-scope widgets had a documented `resources/read` gap at
  verification time.

**OpenClaw** — source: <https://docs.openclaw.ai/cli/mcp>.

- `openclaw mcp add <name> --command <exe> --arg <a> ... --cwd <dir>`, `set`, `configure`, `unset`
  (removal, fails if absent), `list/show/status/doctor/probe --json`, `doctor --probe` and `probe`
  open a live session, `doctor` warns on literal sensitive `env`/`header` values. (V)
- `openclaw mcp reload` disposes cached runtimes for the current CLI process only; Gateway/agent
  processes need their own reload or restart. (V)
- Consequence: scope `gateway`, binding `absolute_path` via `--cwd`, cap
  `connected_restart_required`; the saved definition is distinct from the live probe, so `Verify`
  runs `doctor --probe` or the self-probe.

**Grok Build** — sources: <https://docs.x.ai/build/features/mcp-servers>,
<https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-pager/docs/user-guide/05-configuration.md>.

- `grok mcp add --scope project <name> -- <cmd...>` writes `.grok/config.toml` in the current
  directory; Grok walks from cwd to the git root and a project server with the same name replaces
  a user server entirely. `grok mcp list --json`, `grok mcp doctor [name] --json`,
  `grok mcp remove <name>`, and `grok inspect` (origins) exist. (V)
- `${VAR}` expands in command/args/env at load; `startup_timeout_sec` 30, `tool_timeout_sec` 6000.
  Project `.grok/config.toml` contributes only `[mcp_servers]`, `[plugins]`, `[permission]`, and
  `[mcp] max_output_bytes`. (V)
- Grok also imports `~/.claude.json`, `.cursor/mcp.json`, and project `.mcp.json` unless
  `[compat.claude] mcps = false` / `[compat.cursor] mcps = false`. (V)
- Consequence: `AlsoLoads` is recorded so AT114-207/AT114-209 can detect the duplicate-catalog case
  when Cursor or Claude shared configs already carry the Atlas entry.

**Generic** — source: <https://modelcontextprotocol.io/specification/2025-11-25/server/tools>.

- There is no universal client configuration or health interface; the only universally valid
  proof is a real MCP `initialize` → `tools/list` → tool call against the exact command, which is
  what the self-probe and the test conformance host do. (V)
- Consequence: cap `portable_ready`; `connected` only via `standard_config`/`custom_adapter`
  after a conformance-host run; `MCPApps = unsupported`.

## 8. Deviations from the plan text

1. Two extra interface methods (`Target`, `Capabilities`) — see §2.
2. Nine states plus `ConnectionKind` instead of AT114-208's two extra state names — see §3.1
   (DEC-071).
3. `--expected-workspace-id` on every binding, not only on `verified_cwd` — see §4.1 (DEC-072).
4. `"type": "stdio"` is always rendered in JSON forms — Cursor requires it.
5. The server name is `atlas-<12 hex>` derived from the workspace UUID rather than the plan's
   illustrative `atlas-workspace_ab12cd`; the plan's requirement ("derived from workspace ID, not
   project name") is met and the name is a valid TOML bare key, JSON key, and CLI argument.

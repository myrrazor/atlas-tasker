## Sprint 114.4 — automatic local checkpoints

### AT114-401 — Extract a shared canonical snapshot builder

**Implementation**

Refactor the existing backup collector so both manual backups and Git checkpoints use the same:

- Path allowlist.
- Symlink policy.
- File hashing.
- Manifest construction.
- Scope resolution.
- Schema checks.
- Sensitive-state exclusions.

Do not maintain separate "manual backup files" and "automatic backup files" lists.

Manual `tracker backup create` behavior must remain compatible.

**Acceptance**

- Existing backup fixtures pass unchanged.
- New Git checkpoint and existing archive contain equivalent canonical records for the same scope.
- SQLite index, locks, private keys, remotes, approvals, and runtime state remain excluded.

### AT114-402 — Durable backup outbox and watermarks

**Implementation**

After a canonical Atlas mutation:

- Record workspace as backup-pending.
- Record earliest unbacked timestamp.
- Record event-stream watermarks.
- Record no ticket text or credentials.
- Keep mutation latency independent of network.

Worker startup reconstructs pending state by comparing:

- Current canonical tree.
- Latest verified checkpoint manifest.
- Event watermarks.

Outbox states:

```text
pending
snapshotting
checkpoint_created
push_pending
pushed_unverified
verified
retryable_failure
blocked
```

**Acceptance**

- Outbox loss does not permanently lose awareness of unbacked changes.
- Mutation succeeds when remote is offline.
- Outbox write failure produces a health warning and remains reconstructable.
- Concurrent mutations coalesce safely.
- State writes are atomic and durable.

### AT114-403 — Isolated local backup Git repository

**Implementation**

Store the backup repository outside the workspace under the user data directory.

Use Git plumbing or an isolated temporary index to create commits without touching the user
repository.

Requirements:

- No `git add -A`.
- No user index.
- No user HEAD.
- No checkout into the source workspace.
- Fixed backup author identity.
- Generic commit subjects.
- Atlas-only tree.
- One local ref per workspace replica.
- No shell command interpolation.
- Exact Git executable validation.

Suggested ref:

```text
refs/heads/atlas-backup/v1/<workspace-id>/<replica-id>
```

**Acceptance**

Before and after checkpoint creation, prove:

- User HEAD unchanged.
- Current branch unchanged.
- Git index hash unchanged.
- Staged files unchanged.
- Unstaged files unchanged.
- Untracked files unchanged.
- Merge/rebase state unchanged.
- No application source appears in backup tree.

### AT114-404 — Automatic trigger policy and recursion prevention

**Implementation**

Defaults:

```text
quiet-period debounce:     30 seconds
maximum unbacked delay:    5 minutes
maximum events/checkpoint: 100
```

Trigger only after successful canonical mutations.

Exclude:

- Backup-created bookkeeping.
- Backup verification bookkeeping.
- Restore-plan events.
- Automatic-backup health updates.
- Sync status events that do not change recoverable state.
- Index rebuilds.
- Read operations.
- Worker state changes.

Prefer a canonical-state-change classifier over a fragile filesystem watcher.

**Acceptance**

- One ticket move eventually produces one checkpoint.
- Twenty rapid operations coalesce.
- Continuous activity still checkpoints by maximum delay.
- Creating a checkpoint cannot recursively schedule another checkpoint forever.
- No network work occurs on the mutation response path.

### AT114-405 — Checkpoint idempotency and crash recovery

**Implementation**

Logical checkpoint identity derives from:

- Workspace ID.
- Replica ID.
- Canonical tree hash.
- Event watermarks.
- Target.

If canonical state is unchanged, do not create another commit.

Inject crashes:

- Before snapshot.
- During snapshot.
- After manifest.
- After Git objects.
- Before local ref update.
- After local ref update.
- Before push.
- After push but before acknowledgement.
- Before remote verification.
- After verification but before state persistence.

**Acceptance**

- Recovery never creates conflicting duplicate checkpoints.
- An already-pushed commit is discovered and verified.
- Partial objects are harmless and collectable.
- No checkpoint is reported verified before remote verification.
- Source workspace remains writable after worker recovery.

### AT114-406 — Local status, health, and pre-destructive checkpoints

**Implementation**

Add:

```text
tracker backup auto status
tracker backup run --now
tracker backup tick
tracker backup watch
tracker doctor
```

Expose:

- Last canonical change.
- Last local checkpoint.
- Unbacked event count.
- Oldest unbacked age.
- Worker state.
- Last error class.
- No raw remote credential or sensitive URL.

Before high-risk local operations such as restore, compact, destructive archive actions, or large
imports, create or require a verified local checkpoint according to existing governance policy.

**Acceptance**

- Status is accurate after restart.
- Manual run and automatic worker share one implementation.
- Pre-destructive checkpoint failure blocks the destructive action where policy requires it.
- Read-only backup status is available to MCP.
- Backup configuration remains unavailable to workflow agents.

### AT114-407 — Local backup performance and scale

**Test datasets**

- 10,000 tickets.
- 100,000 events.
- Large descriptions.
- Many evidence and run records.
- 10,000 checkpoint commits.

**Targets**

- Mutation-to-outbox overhead: bounded and measured separately from network.
- Snapshot lock held only during consistent capture.
- Network push outside Atlas write lock.
- No unbounded goroutines or retry timers.
- Local Git maintenance triggered only by explicit thresholds.
- Disk growth reported through status.
- Large unchanged files reused through Git object identity.

### Sprint 114.4 gate

A local checkpoint must survive source workspace deletion and restore into a new directory through
the existing restore-planning boundary.

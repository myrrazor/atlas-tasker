# Atlas Tasker v1.10 Implementation Plan

v1.10 adds an optional local browser Kanban board over the existing Atlas services.

The board is launched from the current workspace:

```bash
tracker web serve --open
```

The web surface is local-first only. It does not introduce hosted mode, accounts, a remote API product, storage redesign, or a second source of truth. Reads continue through `QueryService`; writes continue through `ActionService`; Markdown snapshots, JSONL events, and the SQLite projection keep their current roles.

## Architecture

- `internal/web` owns the HTTP server, embedded templates/assets, route handlers, security middleware, and web view models.
- `internal/cli` owns `tracker web serve`, `tracker web open`, and `tracker web status`, and passes the already-opened workspace services into `internal/web`.
- Web mutations set event metadata `surface: "web"` so history remains auditable across CLI, shell, TUI, MCP, and browser use.

## Feature Slices

- `WEB-901`: command contract, docs, security model, `EventSurfaceWeb`.
- `WEB-902`: secure local HTTP server, embedded templates/assets, token/session/CSRF/security headers.
- `WEB-903`: read-only board, ticket detail drawer, filters, XSS-safe rendering.
- `WEB-904`: create/edit/comment/move/request-review/approve/complete/assign/label handlers.
- `WEB-905`: vendored SortableJS cross-column drag/drop with button fallback.
- `WEB-906`: search, saved views, URL state, compact/comfortable browser preference.
- `WEB-907`: approved minimal dark Atlas design, responsive layout, accessibility pass.
- `WEB-908`: docs, smoke coverage, screenshots, release validation.

## Non-Goals

- Hosted server mode.
- Login/auth system.
- Cloud sync service or remote HTTP API product.
- WebSocket collaboration.
- Raw unsanitized Markdown rendering.
- New canonical rank/reorder model.

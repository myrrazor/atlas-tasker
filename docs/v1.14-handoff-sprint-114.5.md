## Sprint 114.5 — off-device Git backup and restore

### AT114-501 — Backup target configuration

**Implementation**

Add:

```text
tracker backup target add
tracker backup target list
tracker backup target view
tracker backup target edit
tracker backup target remove
tracker backup auto enable
tracker backup auto disable
```

Target fields:

- Target ID.
- Type: Git.
- Remote URL.
- Enabled.
- Default workspace scope.
- Verification policy.
- Optional transport timeout.
- No stored credential.

Rules:

- Never infer target from project origin.
- Reject credentials embedded in URLs.
- Require explicit confirmation of data boundary.
- Warn when target privacy cannot be verified.
- Refuse a confirmed public GitHub repository by default unless an explicit advanced override is
  independently approved.
- Use existing SSH agent or Git credential helper.

**Acceptance**

- Target config remains local-only.
- Target URL redacted in normal diagnostics.
- Removal does not delete remote data.
- Existing sync remotes are not silently converted into backup targets.

### AT114-502 — Fast-forward remote publication and verification

**Implementation**

For every checkpoint:

1. Read expected remote ref.
2. Confirm ancestry.
3. Push ordinary fast-forward update.
4. Reject divergence.
5. Query/fetch remote ref.
6. Verify exact commit.
7. Verify tree and manifest.
8. Record verified.

No:

- Force push.
- Automatic merge.
- Automatic remote deletion.
- Automatic conflict resolution.

**Acceptance**

- Push success alone is not considered verified.
- Remote ref must equal expected commit.
- Fetched manifest must match expected hash.
- Interrupted push resumes.
- Remote divergence produces `blocked_remote_diverged`.
- Ticket writes remain available while backup is blocked.

### AT114-503 — Replica-specific histories and multi-machine behavior

**Implementation**

Generate a 128-bit local replica ID on first enablement.

Each machine writes its own ref:

```text
atlas-backup/v1/<workspace-id>/<replica-id>
```

Restore discovery groups checkpoints by:

- Workspace.
- Replica.
- Created time.
- Atlas version.
- Last event watermarks.

Do not auto-merge backup histories.

**Acceptance**

- Two machines never fight over one ref.
- Copying a workspace does not copy local replica identity.
- Reinstall on the same machine can recover existing identity.
- Replica reset is explicit.
- Restore view clearly distinguishes streams.

### AT114-504 — Retry, offline, authentication, and divergence handling

**Implementation**

Suggested backoff:

```text
initial: 30 seconds
multiplier: 2
maximum: 30 minutes
jitter: full jitter
one retry timer per workspace/target
```

Classify:

```text
offline
dns_failure
authentication_failed
permission_denied
remote_missing
remote_diverged
timeout
corrupt_remote_checkpoint
retryable_transport_failure
```

**Acceptance**

- No retry storm.
- No duplicate timers.
- Auth failures do not retry aggressively.
- Correcting credentials allows next retry to succeed.
- Remote divergence remains blocked until explicit operator action.
- Worker shutdown leaves no child Git process.
- Git stderr is sanitized.

### AT114-505 — Explicit user-level scheduling

**Implementation**

Support three execution modes:

```text
tracker backup tick
tracker backup watch
tracker backup schedule install
```

Platform adapters:

- macOS user LaunchAgent.
- Linux user systemd service/timer.
- Foreground watch fallback.

Requirements:

- Explicit consent.
- No root.
- Exact binary and workspace identity.
- Plan before install.
- Status.
- Safe removal.
- Repair after workspace or binary move.
- No hidden service from ordinary `tracker init`.

**Acceptance**

- Scheduler install is idempotent.
- Scheduler removal removes only Atlas-owned service files.
- Service files use restrictive permissions.
- Unexpected symlink or ownership fails.
- Moved workspace becomes repair-required.
- Uninstall does not delete backups.

### AT114-506 — Remote checkpoint discovery and restore integration

**Implementation**

Add:

```text
tracker backup remote list
tracker backup remote verify <checkpoint>
tracker backup remote restore-plan <checkpoint>
tracker backup remote restore-apply <checkpoint> --yes
tracker backup drill --target <target>
```

Restore sequence:

1. Fetch to temporary isolated repository.
2. Resolve selected checkpoint.
3. Verify workspace and schema.
4. Verify commit/tree/manifest.
5. Verify file hashes and optional signatures.
6. Materialize to temporary directory.
7. Pass files to existing restore planner.
8. Show create/update/skip/block.
9. Recompute plan under write lock.
10. Apply approved Atlas paths only.
11. Reindex.
12. Run doctor.
13. Record restore event.

**Acceptance**

- No `git reset --hard`.
- User source files untouched.
- User branch and index untouched.
- Conflict produces plan, not silent overwrite.
- Wrong workspace requires explicit cross-workspace restore mode.
- Unsupported future schema blocks safely.
- Malicious path and symlink entries fail.

### AT114-507 — Backup health UI, MCP read tool, retention, and recovery drills

**Implementation**

Web board receives a backup-health section showing:

- Automatic backup enabled.
- Last local checkpoint.
- Last remotely verified checkpoint.
- Unbacked events.
- Oldest pending age.
- Worker/scheduler state.
- Restore-drill age.
- Current failure class.

MCP receives only:

```text
atlas.backup.status
```

The default workflow profile may read backup health but may not:

- Change target.
- Disable backup.
- Restore.
- Prune.
- Create a remote.
- Override divergence.

Retention:

- Local generated archives and temporary state receive bounded retention.
- Remote Git history remains append-only by default in v1.14.
- Any remote pruning is plan/apply, never automatic.
- Git object maintenance is local and threshold-driven.

**Required drill**

1. Create and modify representative Atlas work.
2. Wait for automatic checkpoint.
3. Verify remote ref.
4. Remove the local test workspace.
5. Restore into an empty directory.
6. Reindex.
7. Run doctor.
8. Compare canonical manifest.
9. Confirm private keys, runtime state, and credentials were not restored.

### Sprint 114.5 gate

No off-device backup claim until the drill passes against a separate private Git repository from a
clean restore directory.

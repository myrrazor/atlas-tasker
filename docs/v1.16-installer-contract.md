# v1.16 installer contract

This document describes installer verification, prerequisites, prompts, and failure behavior. For the short setup path, see [installation](installation.md).

## Default success path

1. Install `curl`, `tar`, a SHA-256 tool, and GitHub CLI (`gh`).
2. `curl -fsSL .../scripts/install.sh | sh` fetches the published archive.
3. The script checks the destination, checksum, and build provenance **before**
   writing `tracker`.
4. Next command is `tracker init` in the project, then restart detected agents.

The installer does not initialize the directory `curl | sh` happened to run in
unless a TTY user explicitly answers **yes** to the shown path. Unattended
installs never init, never run `tracker setup`, and never edit shell profiles.

`SKIP_INTEGRATIONS=1` still suppresses the optional TTY prompt. If the current
directory already has `.tracker/workspace.json`, the prompt is skipped.

## Provenance

Default `VERIFY_ATTESTATIONS=1`. The script does **not** call
`gh attestation verify ARCHIVE --repo ...` without `--bundle` (that path asks
for GitHub login in an empty `GH_CONFIG_DIR`).

Local verification command:

```text
gh attestation verify ARCHIVE \
  --repo myrrazor/atlas-tasker \
  --bundle attestation-bundle.jsonl \
  --signer-workflow myrrazor/atlas-tasker/.github/workflows/release.yml \
  --source-ref refs/tags/<resolved-tag>
```

Bundle sources, in order:

1. `ATTESTATION_BUNDLE_URL` when set (advanced override)
2. release asset `attestation-bundle.jsonl`
3. anonymous GitHub attestations API
   `GET /repos/myrrazor/atlas-tasker/attestations/sha256:<archive-digest>`
   (only when not a `RELEASE_BASE_URL` fixture still pointed at
   `https://api.github.com`)

Checksum mismatch, missing bundle, unwrap failure, or `gh` identity failure
refuses the install. There is no checksum-only fallback.

`VERIFY_ATTESTATIONS=0` remains an explicit local-fixture override, not a
default.

`gh` stays a required prerequisite for the default path. The one-line installer
is honest about that. python3 is needed only to unwrap API JSON when no jsonl
asset is present.

## Fail-closed checks (before the archive download)

- missing `curl` / `tar` / SHA-256 / `install` / `gh` (when attestations on)
- `BIN_DIR` must be an absolute writable directory (or a creatable path)
- default `/usr/local/bin` failures tell the user to set `BIN_DIR="$HOME/.local/bin"`

After a successful install, if `BIN_DIR` is not on `PATH`, print a session
`export PATH=...` warning. Profiles are left alone.

Receipt format `atlas_install_receipt_v1` is unchanged. Init failure after a
verified copy keeps the binary and receipt.

## Packaging

The release workflow exports `actions/attest-build-provenance` `bundle-path` as
`dist/attestation-bundle.jsonl` and publishes it next to the archives. The pinned
action documents this output as a file. Hosted verification is recorded on the
[v1.16 release page](https://github.com/myrrazor/atlas-tasker/releases/tag/v1.16.0).

## Related behavior

`tracker update` still uses online `gh attestation verify` without `--bundle`.
Anonymous installation and anonymous update are different claims. See [updating](guides/updating.md) and [client compatibility](v1.16-client-compatibility.md).

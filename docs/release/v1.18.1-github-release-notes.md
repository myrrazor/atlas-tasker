# Atlas Tasker v1.18.1

Fix release, 2026-10-30. It fixes the install, update and MCP approval problems found in the v1.18.0 acceptance run. No breaking changes: tracker data formats and the MCP tool set are unchanged, and the CLI has one additive JSON change (`tracker mcp approvals revoke --json` now also reports `scope` and `found`, from #179).

## What changed

- **GitHub CLI 2.102.0 floor and a real Option A check** ([#177](https://github.com/myrrazor/atlas-tasker/pull/177)). The installer and `tracker update` (`--check`, `--dry-run` and `--yes` alike) need `gh` 2.102.0 or newer. They check `gh --version` before downloading anything and stop with: "Atlas Tasker needs GitHub CLI (gh) 2.102.0 or newer. Upgrade it from https://cli.github.com/ (distro packages are often older) and re-run." 2.97.0 and 2.102.0 fixed `gh attestation verify` signer-policy bypasses (GHSA-mm27-mwq9-fr5g, GHSA-4mq3-hpgx-9cx8). Distro packages such as Ubuntu 24.04's gh 2.45.0 and Debian 13's 2.46.0 are too old. The no-script install (Option A) is now one block that runs in a `set -e` subshell and starts with a numeric `gh` check. It stops before any download when `gh` is missing, unreadable or too old, without closing your terminal, and removes its temporary folder on success.
- **Installer falls back to `~/.local/bin`** (#177). When `/usr/local/bin` isn't writable and `BIN_DIR` isn't set, the installer uses `~/.local/bin` (creating it) and prints the `PATH` line to add, instead of failing. It never runs `sudo` unless you set `USE_SUDO=1`. An explicit `BIN_DIR` is used as is.
- **MCP machine-scoped approvals** ([#178](https://github.com/myrrazor/atlas-tasker/pull/178)). `tracker mcp approve-operation` stores approvals for machine-scoped tools such as `atlas.settings.grant_discovery` in the machine state dir, where the global MCP server looks for them. Before, those calls failed with "operation approval not found".
- **`approvals revoke --json` reports `scope` and `found`** ([#179](https://github.com/myrrazor/atlas-tasker/pull/179)), so you can tell which store held the revoked approval.
- **Token-free attestation in `tracker update`** ([#180](https://github.com/myrrazor/atlas-tasker/pull/180)). The updater downloads the release's `attestation-bundle.jsonl` and runs `gh attestation verify` with the installer's exact policy: `--bundle`, `--repo myrrazor/atlas-tasker`, `--signer-workflow myrrazor/atlas-tasker/.github/workflows/release.yml` and `--source-ref refs/tags/<tag>`. No GitHub login or token is needed. A missing or empty bundle stops the update; there is no weaker fallback.

## Upgrade notes

- **From v1.18.0 or older, reinstall instead of running `tracker update`.** Those updaters run `gh attestation verify <archive> --repo myrrazor/atlas-tasker` without `--bundle`, so `gh` has to query the GitHub API and the update fails with "attestation verification failed" unless a GitHub token is available. Reinstall v1.18.1 with the installer or the [no-script steps](https://github.com/myrrazor/atlas-tasker/blob/v1.18.1/docs/install-without-script.md). From v1.18.1 on, `tracker update` works without a token.
- If you can't reinstall, an old updater still works when `gh` is logged in or `GH_TOKEN` is set. Running it with `--skip-attestations` or `VERIFY_ATTESTATIONS=0` also works, but that is at your own risk: it skips build-provenance verification and checks only `checksums.txt`.
- Upgrade `gh` to 2.102.0 or newer from https://cli.github.com/ before installing or updating.

See the [full changelog](https://github.com/myrrazor/atlas-tasker/blob/v1.18.1/CHANGELOG.md) and the [updating guide](https://github.com/myrrazor/atlas-tasker/blob/v1.18.1/docs/guides/updating.md).

## Install

GitHub CLI (`gh`) 2.102.0 or newer is required for attestation verification. No GitHub login is needed.

```sh
curl -fsSL https://raw.githubusercontent.com/myrrazor/atlas-tasker/v1.18.1/scripts/install.sh | sh
```

Set `BIN_DIR` for a different install location. The installer verifies checksums and GitHub build attestations before copying the binary. Existing v1.18.1 installs can run `tracker update --yes`.

# Atlas Tasker v1.18.3

Small fix release, 2026-10-31. No breaking changes: the CLI, JSON output and MCP tool set are unchanged, and existing workspaces need no migration.

## What changed

- **TUI live board follows SQLite `data_version`** ([#196](https://github.com/myrrazor/atlas-tasker/pull/196)). The watch loop no longer compares index file mtimes. A commit that lands before the next tick is still loaded when a WAL spill moves the file stamp first and the commit itself does not move it again. If that generation cannot be read, the next tick still reloads instead of leaving the board on the last snapshot.
- **Release rehearsal no longer stops on `dirty_repo`** ([#194](https://github.com/myrrazor/atlas-tasker/pull/194)). The script commits the workspace files `tracker init` creates before it dispatches. Extra sync workspaces use separate directory names so their default projects do not clash. When `VERSION` is not set, it uses the latest `vMAJOR.MINOR.PATCH` git tag instead of a hardcoded version.

## Upgrade notes

- From v1.18.2, `tracker update --yes` works. From v1.18.0 or older, reinstall with the installer or the [no-script steps](https://github.com/myrrazor/atlas-tasker/blob/v1.18.3/docs/install-without-script.md) (see the v1.18.1 notes).

See the [full changelog](https://github.com/myrrazor/atlas-tasker/blob/v1.18.3/CHANGELOG.md).

## Install

GitHub CLI (`gh`) 2.102.0 or newer is required for attestation verification. No GitHub login is needed.

```sh
curl -fsSL https://raw.githubusercontent.com/myrrazor/atlas-tasker/v1.18.3/scripts/install.sh | sh
```

Set `BIN_DIR` for a different install location. The installer verifies checksums and GitHub build attestations before copying the binary.

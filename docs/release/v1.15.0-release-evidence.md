## PR #155 macOS recovery correction

The first hosted macOS run failed `TestRemoteRecoveryDrill`: rebuilding the same remote checkpoint could change archive hashes because the bundle manifest and tar entries used current timestamps. Controlled file-mtime changes reproduced the failure; advancing the destination clock exposed the manifest-time case as well.

Remote reconstruction now uses the verified checkpoint creation time for both metadata layers. Normal export timestamps and all archive, manifest, plan, file-hash, and remote-ref checks remain intact. Regressions cover identical bytes across changed mtimes and independent fetches an hour apart, successful plan/apply, tampered-content refusal, and normal export timestamp preservation. See DEC-104 and the appended local validation output. Hosted check results are attached to the current PR commit.

## PR #155 stability correction

The next hosted run passed macOS, Ubuntu, security, workflow policy, and all three stability race packages. Its final event-reader fuzz target reported only a coordinator deadline after 7595 executions. The separate 60-second package timeout did not prevent the two-second fuzz timer from triggering Go's cancellation race, consistent with [golang/go#75804](https://github.com/golang/go/issues/75804).

The stability script now uses execution counts rounded upward from that run's measured workload for every fuzz target. It retains the package guard, all targets, race testing, and fail-fast exits. These finite smoke workloads do not claim identical random coverage or replace longer fuzzing. See DEC-105, the complete local stability output in `TEST_STDOUT.log`, and the hosted checks attached to the current PR commit.

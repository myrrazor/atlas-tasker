## Product verification

- **First use and Home:** Actual fresh init, unchanged repeated init, a second workspace, and bare tracker outside a workspace all succeeded and reused the same service identity and port. A real child-process regression covers the startup-lock issue. Isolated provider tests cover managed argv, opt-outs, and partial setup results.
- **Registry and boundaries:** Tests cover approved discovery roots, persisted purpose-bound grants, expiry/replay, symlink changes, moved/replaced/copied roots, explicit repair, and concurrent same-ID tickets in different workspaces.
- **Browser:** Home and Kanban were inspected at 320, 390, and 1440 pixels, in light and dark themes, with keyboard navigation. Actual browser saves persisted notes and retained the project URL. A concurrent CLI edit caused a stale browser save to fail while preserving typed input and the newer canonical ticket.
- **Terminal and TUI:** The table is the default; Kanban is optional. Actual PTY output was checked at 40, 80, 120, and 180 columns. A 180-ticket fixture remained navigable through the last row. Narrow TUI, selection, detail loading, plain output, and color-independent status labels were checked. Product screenshots in README and site assets are captures of synthetic local data from the actual UI.
- **MCP:** Global inventory exposes 123 gated capabilities and matches CLI schema, SDK resources, and resource templates. Tests cover scope, actor/reason, exact high-impact approval targets, redaction, notifications, and stored restore-plan binding. The optional board App was rendered in a local sandbox host with the stable 2026-01-26 initialization, theme, sizing, result, cancellation, and teardown messages.
- **Recovery:** Local Git fixtures verify canonical-only isolated checkpoints, source-index isolation, coalescing/crash recovery, legacy state continuity, independent remote fetch/hash validation, divergence refusal, and immutable plan-bound clean-directory restore.
- **Uninstall:** An isolated executable rehearsal previewed and applied removal, preserved all 56 recorded board/state/backup files byte-for-byte, retained unrelated client settings, and passed doctor after reinstall. Unit tests cover service-stop failure, receipt tampering, symlinks, and package-manager ownership.
- **Website:** Final desktop/mobile checks found no page overflow, broken images, missing image alt attributes, external resources, or marketing cookies. Copy loading/success/failure states and nested custom 404 recovery were exercised. Favicon, robots, sitemap, page titles/descriptions, social preview, privacy/terms, and navigation are covered by the site contract suite. No cookie banner or analytics was added.

## Evidence boundaries

Disposable local Git remotes verify protocol and integrity behavior; they do not prove an off-device disaster-recovery drill. Injected client/service tests and the synthetic MCP Apps host do not prove every real client has restarted, connected, or rendered the App. No remote merge, tag, release, scheduler rollout, or website deployment is included in this submission.

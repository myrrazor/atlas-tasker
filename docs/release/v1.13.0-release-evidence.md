# v1.13.0 Release Preparation

Status: **candidate under preparation; not published**. The owner authorized the
workflow-consistency PR and preparation for the next stable release on 2026-09-09.
The current published stable is [v1.12.0](https://github.com/myrrazor/atlas-tasker/releases/tag/v1.12.0).

## Scope and compatibility

[The 22-finding assessment](workflow-consistency-review-2026-09-09.md) records the
agreed fixes, retained safeguards, and the live-index issue that did not reproduce.
The candidate includes:

- Separate Canceled board columns and visible assignees across the affected views.
- Consistent CLI identity resolution, explicit reassignment before a different
  worker can claim, and rejection of new schedules at or before the current time.
- Effective review presets, inherited project policy, a configured reviewer, and
  permission checks before review approval can complete work.
- Six additional MCP workflow tools and explicit startup workspace bootstrap.
- Portable generated guidance and current documentation, website copy, and board
  captures.

Version 1.13 is a minor release because it adds public MCP tools and a startup
option. Consumers must treat `columns.canceled` separately from `columns.done`.
Scripts that relied on an implicit owner must pass `--actor`, set `TRACKER_ACTOR`,
or configure `actor.default`. Applying a review preset clears project `open`
overrides so they inherit the selected workspace policy; explicit non-open project
overrides and custom agent/profile/runbook definitions remain unchanged. See
[team presets](../guides/team-presets.md) before applying a preset to an existing
workspace.

No new runtime dependency or storage-schema version is introduced. Read-only MCP
defaults, strict schemas, separate client registration, external approval issuance,
and the existing ready-before-work workflow remain deliberate boundaries.

## Remaining release gates

1. Required hosted checks pass on the final PR head, and the owner approves and
   merges the PR into `testing`.
2. The approved source completes the `testing` to `main` promotion, including the
   active code-owner review requirement and exact promoted-head checks.
3. Publish `v1.13.0-rc1` from that approved commit; verify all four archives, checksums,
   SBOM, attestations, clean install, metadata, packaged workflow, and MCP/installer
   harnesses against the downloaded native executable.
4. Publish `v1.13.0` after hosted RC proof and stable sign-off, then repeat stable
   artifact and unpinned-latest installation verification.
5. Deploy and verify the matching public site, including source-byte comparison,
   links, responsive rendering, and agent onboarding. Record hosted evidence on
   the release pages without moving existing tags.

Local proof does not satisfy hosted artifact or production deployment gates.
No v1.13 tag, stable release, or production deployment is created by preparation.

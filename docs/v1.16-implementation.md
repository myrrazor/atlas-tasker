# v1.16 implementation and acceptance contract

Scope for PR #158, targeting main. The owner authorized completion through the v1.16 release and website publication on resumption. This document defines the acceptance contract; verification results are recorded separately.

## Outcome

A new user can install Atlas with clear prerequisites and provenance verification, connect supported local coding clients, and manage everyday workspace/project/ticket work from Atlas Home and Kanban. Existing PR #158 demo assets and changes are retained. Terminal and TUI keep the table default; browser keeps Kanban. Current screenshots and copy describe the implemented behavior and identify the version and provenance of recorded demos.

## Boundaries

Browser mutations use the same action/query services and actor/reason/policy/locking/event/index contracts as CLI/MCP. Path selection does not authorize an implicit whole-machine crawl or unrestricted writes. Existing session, Origin/Host, CSRF, read-only and stale-revision protection remain.

Everyday browser functionality is inventoried in the browser-management guide. Advanced signing, destructive storage maintenance, agent process execution and machine administration do not belong in ordinary ticket forms. No new autonomous reviewer wakeup runner or hosted remote agent transport is included in this scope. Existing automation descriptions must accurately describe their prerequisites.

The product remains a local single-user tool for cooperative coding agents. Client-owned trust, authentication and restart requirements are not bypassed or represented as completed automatically. A configured integration is distinct from verified native discovery and an actual tool call.

## Validation

Run required Go tests/vet/build, installer harness, MCP framing/profile/workflow harness, managed-workflow harness, browser/site Node contracts, affected security/race tests, stability lane and release-relevant supply-chain checks. Capture commands and full sanitized stdout in TEST_STDOUT.log. Serialize expensive local runs.

Manually validate Home creation/attachment, new/edit/remove tickets, assignment, review, persisted state and conflict recovery with synthetic data. Inspect compact phone, tablet and desktop layouts, keyboard/focus, empty/long/error states, and existing large-board behavior. Record limits honestly; no claim that every hosted client or off-device recovery has been exercised unless it has.

Public output must preserve the project identity and exclude private names, local paths, credentials and unrelated client state. Keep audit transcripts private; publish only sanitized, reproducible evidence.

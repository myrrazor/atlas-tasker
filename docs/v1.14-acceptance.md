# Atlas Tasker v1.14 Acceptance Tracker

Ticket-by-ticket status for the 45 units of the
[v1.14 implementation plan](v1.14-implementation-plan.md). AT114 IDs are plan IDs, not GitHub
issue numbers. "Result" records what was actually observed (test output, behavior), never what is
expected. Full sanitized gate output for each sprint is committed as `TEST_STDOUT.log` on the branch
(the repository's existing convention) and summarized in
[docs/release/v1.14-baseline-evidence.md](release/v1.14-baseline-evidence.md).

Status values: `done` (reviewed evidence recorded), `implemented` (evidence recorded, awaiting
independent review), `in_progress`, `not_started`, `blocked`. For a Sprint 114.0 ticket, `done
(contract scope)` means the contract, model, or document exists, is tested where it is code, and
passed independent review; the implementation obligations it hands to later tickets are listed in
its "Remaining dependencies" column and stay with those tickets.

Sprint 114.0 was approved at contract scope on 2026-09-10: its bounded, independent post-fix review
closed with no P0 or P1 (13 of 13 adapted reproductions pass; dispositions and the post-fix outcome
in [docs/release/v1.14-s0-review-round1.md](release/v1.14-s0-review-round1.md)), Codex approved the
candidate, and the Sprint 114.0 pull request is
[myrrazor/atlas-tasker#145](https://github.com/myrrazor/atlas-tasker/pull/145) into `testing`.
Only the owner merges and promotes.

The owner runs Sprints 114.1–114.6 manually from the remaining-sprint handoff package,
[docs/v1.14-handoff-index.md](v1.14-handoff-index.md) (verbatim plan slices plus the owner's
execution directions); the Sprint 114.0 pull request is its prerequisite, and each later feature
branch starts from the `dev` that contains the approved Sprint 114.0 contracts, as the package's
publication note states. If `dev` does not yet contain them when a sprint is started, the owner
must arrange that integration first.

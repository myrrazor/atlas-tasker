## Sprint 114.6 — integrated hardening and v1.14 release candidate

**Implementation**

- Workspace initialization.
- Agent detection.
- Skill refresh.
- MCP registration.
- Agent/team mapping.
- Managed-mode configuration.
- Optional backup target.
- Optional scheduler.
- First connection verification.
- First backup verification.
- Final status.

**End-to-end acceptance**

From an empty test repository:

1. Install Atlas.
2. Run setup.
3. Detect all available agents.
4. Select all six targets.
5. Install the existing skill for all six.
6. Register MCP for all applicable targets.
7. Configure identities.
8. Configure managed mode.
9. Configure private Git backup.
10. Install explicit user scheduler.
11. Verify providers.
12. Run first checkpoint.
13. Verify remote.
14. Run `tracker setup status`.
15. Receive no false connected state.

### AT114-602 — v1.13 upgrade, repair, and relocation

**Required migrations**

- Existing integration-only installs.
- Existing skills at v1.13.
- Existing custom `AGENTS.md` and `CLAUDE.md`.
- Existing manual MCP entries.
- Existing server named `atlas`.
- Existing manual backups.
- Existing sync remotes.
- Existing team presets.
- Existing workspaces with no local setup manifest.

**Cases**

- Binary path changed.
- Workspace moved.
- Workspace copied.
- Provider upgraded.
- Provider config format changed.
- Provider removed.
- Multiple Atlas workspaces.
- Existing Atlas MCP registration points to wrong workspace.
- Current config was manually edited.

**Acceptance**

- Upgrade never silently rewrites an unmanaged MCP entry.
- Existing backups remain restorable.
- Existing sync behavior unchanged.
- Setup provides a repair plan.
- `tracker update` does not automatically modify provider config.
- User chooses when to run setup repair.

9. All clients see the same Atlas state.
10. No duplicate MCP server or ticket.
11. Backup checkpoint eventually contains the final Atlas state.

### AT114-604 — Security, privacy, concurrency, and performance review

**Setup security**

Test:

- Config path traversal.
- Config symlink.
- Parent-directory symlink.
- Unsafe ownership.
- Writable executable substitution.
- Command injection in workspace path.
- Provider executable substitution.
- Stale setup plan.
- TOCTOU between plan and apply.
- Unmanaged same-name config collision.
- Rollback failure.
- Secret-containing provider config.
- Diagnostics redaction.

**MCP security**

Test:

- Wrong workspace.
- Wrong actor.
- High-impact tool absence.
- Result-size limits.
- Malformed JSON-RPC.
- Unknown arguments.
- Project-name ambiguity.
- Agent cannot modify setup or backup target through workflow profile.
- Status cannot expose private remote URL.

**Backup security**

Test:

- Source-code exclusion.
- Private-key exclusion.
- Credential URL rejection.
- Git config injection.
- Malicious remote ref.
- Malicious checkpoint.
- Path traversal.
- Symlink archive member.
- Manifest tampering.
- Commit/tree mismatch.
- Workspace mismatch.
- Remote divergence.
- Backup recursion.
- Restore conflict.
- Repeated crash recovery.
- No user Git mutation.

**Concurrency and scale**

Test:

- CLI, web, and MCP mutate concurrently while checkpointing.
- Two backup workers contend.
- Two machines back up the same workspace using separate replica refs.
- 100,000 events.
- 10,000 tickets.
- 10,000 checkpoint commits.
- Offline for multiple days.
- Large pending queue.
- Repeated provider repair.
- Many Atlas workspaces in local registry.
- All timers, locks, child processes, and temporary directories return to baseline.

### AT114-605 — Immutable v1.14 release candidate and independent review

> Owner override: the procedural source/binary hashing items in this ticket (exact base/final
> SHA/tree bookkeeping, first-parent list, diff hash, binary and installer hashes, build provenance
> as a *completion gate*) are waived as gates. The remaining functional gates stand.

**Release artifacts**

Produce:

- Exact base SHA/tree.
- Final SHA/tree.
- First-parent commit list.
- Complete diff hash.
- Binary hashes.
- Installer hashes.
- Test manifests.
- Provider versions.
- Backup drill evidence.
- Dependency and vulnerability scans.
- Secret scan.
- License scan.
- SBOM.
- Build provenance.
- Changelog.
- Migration notes.
- Technical setup documentation.
- Recovery documentation.

**Mandatory gates**

- Full Go test suite.
- Race detector for supported packages.
- `go vet`.
- Static analysis.
- Vulnerability scan.
- Installer tests.
- Existing release rehearsal.
- Existing MCP workflow verification.
- All new setup tests.
- All six provider tests.
- All backup tests.
- macOS arm64.
- macOS amd64 where available.
- Linux arm64.
- Linux amd64.
- Clean v1.13-to-v1.14 upgrade.
- Clean new installation.
- Clean disaster restore.
- Independent source/security review.
- Independent runtime reproduction.
- No unresolved P0/P1.
- Every P2 disposition recorded.
- Final worktree clean.
- No raw secrets or private backup contents in evidence.

**Release remains blocked when**

- Any named provider is falsely reported connected.
- Any provider adapter overwrites unrelated configuration.
- Generic is claimed universally connected without verification.
- High-impact MCP tools are enabled by normal setup.
- A normal mutation waits for remote backup.
- Backup touches user HEAD or index.
- Existing origin is silently selected.
- Remote verification is missing.
- Restore bypasses the existing restore planner.
- Backup recursion exists.
- Source or secrets enter a checkpoint.
- Real disaster recovery has not been completed.
- An independent review has unresolved P0/P1.

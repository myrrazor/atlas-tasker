# v1.15 MCP capabilities

Canonical machine registration:

```
tracker mcp serve --global --tool-profile workflow
```

Argv: `["mcp", "serve", "--global", "--tool-profile", "workflow"]`

Grok Build skips dotted MCP names (`atlas.status` → invalid `server__tool`). Atlas-managed Grok registration adds `--tool-name-style portable` on both the global init path and project-scoped `tracker setup`. Portable `tools/list` names are unique underscore forms (`atlas_status`). Default `canonical` names stay dotted for Claude/Codex/Cursor/OpenClaw/generic. Payloads keep canonical `kind` values.

Per-workspace `tracker mcp serve` still defaults to `--tool-profile read`. `--global` cannot combine with `--workspace`, `--init-if-missing`, or `--workspace-from-cwd`. CLI `--global` without an explicit `--tool-profile` uses workflow. High-impact tools stay off unless `--dangerously-allow-high-impact-tools` is added (never in the default registration). `--tool-name-style` defaults to `canonical`.

`tracker mcp schema --global` / `tracker mcp tools --global` match `tools/list` on that server.

## Profiles

| Profile | What it can do |
|---|---|
| `read` | Queries, boards, attention, backup status/list/history/verify/targets, settings get. No writes. |
| `workflow` | Ticket/project/view/bulk/local backup run/restore plan/workspace lifecycle/settings (safe). Actor+reason on writes. |
| `delivery` | Workflow plus dispatch/change/check sync. |
| `admin` | Delivery plus high-impact tools **only** with `--dangerously-allow-high-impact-tools` and a one-time operation approval. |

Read-only tools never call `app.Init` and never set `WriteClientCfg`. `atlas.workspace.init` is a workflow tool. Authorized init uses `app.Init` with shared defaults (`WriteClientCfg` true unless `agents=false` or persisted `agents.auto_install=false`). Tests inject isolated Home/StateDir/LookPath/Runner.

## Global tools

- `atlas.workspace.list|get|status|board_url|init|register|repair|hide|unhide|remove_pointer`
- `atlas.workspace.fork_copy` (high-impact)
- `atlas.settings.grant_discovery` (high-impact)

Workspace-scoped tools keep their existing `atlas.*` names. In global mode every workspace-scoped schema gains optional `workspace_id`. Cross-workspace writes require it. Unambiguous current CWD may omit it.

## Extra workspace tools (CLI/HTTP/MCP parity)

`atlas.attention`, `atlas.activity`, `atlas.project.list`, `atlas.project.update`, `atlas.views.list|get|run|save|delete`, `atlas.ticket.bulk`, `atlas.backup.list|history|verify|targets|run`, `atlas.backup.configure` (high-impact), `atlas.restore.plan`, `atlas.restore.apply` (high-impact), `atlas.settings.get`, `atlas.settings.update`.

`atlas.settings.update` cannot widen discovery roots. That is `atlas.settings.grant_discovery`.

## Resources

`atlas://workspaces`, `atlas://attention`, `atlas://workspace/<id>`, `.../projects`, `.../project/<key>/board`, `.../backup`, `.../activity`.

Templates: `atlas://workspace/{workspace_id}`, `.../projects`, `.../backup`, `.../activity`, `.../project/{project}/board`. `resources/list_changed` fires when workspaces or projects are added. Resource `revision` is the last project `EventID`, not Unix seconds.

MCP Apps: `atlas.board` `_meta.ui.resourceUri` = `ui://atlas/board`, MIME `text/html;profile=mcp-app`. The sandbox document starts JSON-RPC `ui/initialize` (`id`, `protocolVersion` `2026-01-26`, `appInfo`, empty `appCapabilities`). After a matching result it sends `ui/notifications/initialized`. Hosts post `ui/notifications/tool-result` (including `isError`/`content`), `ui/notifications/tool-cancelled`, and `ui/notifications/host-context-changed` (`theme` as `light`/`dark` and `containerDimensions`). Teardown is request `ui/resource-teardown` with an empty result. The app sends `ui/notifications/size-changed` after content/size changes. Ticket text uses `textContent`. `event.source === window.parent`. Resource list and `resources/read` content `_meta.ui.csp` have empty connect/resource/frame domains. Visual UI omits raw localhost UUID board URLs unless the host advertises the `openLinks` capability object. Diagnostics stay behind a details control. Markdown/structured `board_url` remain. Host harness: `internal/mcp/testdata/apps-host/` (synthetic `ws-atlas-demo`; live Node runs use `t.TempDir`).

Global `atlas.board` / `atlas.status` overlay `Machine.BoardURL` (`http://127.0.0.1:<port>/w/<id>/projects/<key>`). Pinned single-workspace output keeps `/board?project=...`. Session/claim secrets are never added.

## High-impact approval targets

`tracker mcp approve-operation --target` is the exact binding MCP consumes. Compound tools use JSON of every material field (keys sorted):

- `atlas.restore.apply` `{"digest":"...","plan_id":"..."}`
- `atlas.workspace.fork_copy` `{"path":"...","workspace_id":"..."}`
- `atlas.backup.configure` `{"action":"add","target_id":"...","url":"..."}`
- `atlas.sync.pull` `{"remote_id":"...","source_workspace_id":"..."}`

`confirm_text` must equal `execute <tool-name> <target>`. An approval for one concrete operation does not authorize another.

Restore: `atlas.restore.plan` returns `CreateRestorePlan`'s `restore_plan_id` / `plan_digest` (`service.RestorePlanBindingDigest`). `atlas.restore.apply` validates that digest against the stored plan and calls `ApplyRestorePlan(planID)`.

directions govern roles, authority, and publication, and they do not add or remove product scope.

## Directions

1. **Roles.** Cursor implements all v1.14 implementation and tests. Codex orchestrates and
   independently verifies; Codex does not implement. The owner now controls Sprints 114.1–114.6
   manually and will run Cursor for each sprint from these handoff documents.
2. **Sprint 114.0 submission only.** The current Cursor task submits the Sprint 114.0 pull request
   only, targeting the `testing` branch. Only the owner merges and promotes. No other pull request is
   opened without the owner's explicit direction.
3. **No external or irreversible action.** No release, deployment, real (off-device) backup target,
   or service/scheduler installation unless the owner later explicitly authorizes it. This applies to
   every sprint, including 114.5 and 114.6: implement and test against synthetic, local, and
   disposable targets. The plan's own rule stands: "Do not publish, tag, release, create a remote
   repository, use a public backup target, or perform any irreversible external action without
   separate explicit owner authorization."
4. **Ceremony waiver — exact extent.** The owner waived the *procedural* source/binary
   SHA/checksum/attestation ceremony (release SHA/checksum/binary attestation, "SHA-bound evidence"
   bookkeeping) as a completion gate. Not waived: the backup product's own integrity requirements
   (canonical tree hashes, manifest hashes, remote commit/tree/manifest verification, file-hash
   verification on restore) and the existing installer security (download checksum and attestation
   verification; "Existing installer security remains unchanged" in AT114-106).
5. **No force push in the backup product.** The plan's "push fast-forward only; never force push,
   merge, pull, or auto-restore" stands. Any forced ref update, including `--force-with-lease`, is
   not an approved alternative; divergence is reported, never forced.
6. **Sprint 114.0 contracts govern clarified semantics.** Operation states, integration states,
   managed-mode semantics, and backup architecture are clarified by the Sprint 114.0 contract
   documents and by decision-log entries DEC-070 onward in the repository (paths below). At handoff
   time Sprint 114.0 has **not** been approved and is still being corrected by the lead. Read those
   documents in the repository at implementation time; do not treat unreviewed changes as approved,
   and do not copy their evolving content into these handoff documents.
7. **No invented requirements.** No deadlines, thresholds, budgets, prices, features, or omissions
   beyond the plan text. Where the plan is silent or a genuine conflict cannot be resolved from the
   plan and the approved contracts, record it explicitly (decision log, acceptance ledger, or a
   conflict note for the owner) and continue with unaffected work; do not fill the gap with an
   assumption.
8. **Gates remain in force.** "No sprint begins until the prior gate has independent review with no
   unresolved P0/P1." Work sprint by sprint; do not collapse sprints into one unreviewed pass.
9. **Honest ledger.** Implemented, tested, pending integration, and deferred are different states.
   Do not claim cross-sprint parity, integration, or acceptance before both sides exist and have
   been exercised.
10. **Public metadata.** Commits use the project's public identity for author and committer
    (`myrrazor <myrrazor@users.noreply.github.com>`), with a pre-seeded
    `Co-authored-by: myrrazor <myrrazor@users.noreply.github.com>` trailer so that no tooling can
    inject a personal identity. Do not disable or modify Git hooks. Before handoff, audit every new
    commit, source file, and generated public artifact for personal names, e-mail addresses, sites,
    profile links, attribution, and machine-local paths; keep raw machine paths and evidence
    private; never include secrets.

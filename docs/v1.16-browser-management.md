# Browser management in v1.16

Create a board in a chosen local directory, then manage the same tickets your coding agents use. Atlas Home and Kanban use the existing CLI services and storage. The terminal and TUI keep their table default; the browser keeps Kanban.

## Product thesis

A technical owner on this machine should be able to stand up a board in a
chosen folder and do everyday ticket work from Home/Kanban without opening a
terminal for each action. Filesystem writes stay purpose-bound. Failures keep
typed values. Soft-delete is not purge and is not runtime archive restore.

## First-use fixes (audit 1 / 2 / 3)

1. **Fresh Home had no board without a terminal grant.** Default Home still
   creates under Atlas boards (`$STATEDIR/boards`) from **Initialize board**.
2. **A chosen existing directory is no longer terminal-only.** Home can review
   an absolute local folder: human session + CSRF + writable mode, canonicalize,
   refuse nested workspaces and broad roots, display the exact path and purpose,
   mint a Home-sourced one-time grant, and consume it only after
   `confirm_path` matches that displayed canonical path. Preview does not
   scaffold. There is no extra JavaScript confirm on that step. While a preview
   is pending, the authorized-root form, approved listings, and CLI grant paste
   stay hidden so the confirm surface is the only grant path. This partially
   supersedes DEC-099; see [DEC-114](v1-decision-log.md#dec-114--home-minted-path-grants-for-existing-directories).
   Child folders under Atlas boards / discovery roots stay a one-step
   authorized-root flow. Raw `path=` on Init/Register is still ignored.
   Listing and resolve inspect every path component from the authorized root
   and refuse if any is a symlink.
3. **Init errors re-render with preserved values**, and success opens the new
   project board.

Ordinary Home settings still cannot widen discovery. No machine-wide crawl.

Implementation: `internal/app/authorized.go` (`PreviewDirectoryGrant`,
`CanonicalExistingDir`, `refuseSymlinkChain`), `internal/app/pathgrant.go`,
`internal/web/home_handlers.go`, `internal/web/templates/home.html`.

## Create / attach contract

| Intent | Authorized input | Server |
|---|---|---|
| Create under Atlas boards / discovery | `root_ref` + relative `folder` | `ResolveAuthorizedDir` → `GrantPath` → consume → `Init` (`SkipHomeService`, `WriteClientCfg=false`) |
| Attach under those roots | same, `create=false` | grant + `Register` |
| Existing directory anywhere on this machine | `POST /actions/workspaces/preview-path` then confirm | `PreviewDirectoryGrant` (no init) → confirm `grant_id` + `confirm_path` → consume → `Init`/`Register` |
| CLI grant paste | `grant_id` without Home `source` | consume; no `confirm_path` |

Preview of an existing absolute directory canonicalizes to a real directory so
the confirm step shows the granted path (ordinary OS links such as `/tmp` are
followed for that display). A symlink *under* an authorized root is still
refused.

## Home init vs MCP vs guidance

Home **Initialize board** still creates the workspace (scaffold, register, and
the first project when that setting is on). That is not a no-op.

`WriteClientCfg=false`, so Home does **not** write editor MCP files (Cursor
`mcp.json`, Claude/Codex/Grok user config, and the rest). Workspace
skill/instruction guidance may still be written when the machine **Agents**
auto-install setting is on; that is guidance, not MCP.

Editor MCP remains `tracker init` (or the documented scoped `tracker setup`)
in the project, then a client restart / trust prompt. `tracker integrations
install` writes skill and instruction files only — it does not register MCP.
Restart and trust stay client-owned.

Workspace **agent profiles** (for ticket assignment) can be created from the
Kanban **Register agent** action. That is not editor MCP.

## Everyday ticket contract

Kanban (and Home-hosted `/w/<id>/projects/<key>`) uses existing services:

| Action | Service | UI |
|---|---|---|
| Create / edit / labels / notes | `CreateTrackedTicket` / `MutateTrackedTicket` | drawer; values kept on error |
| Register agent profile | `SaveAgentProfile` | Board “Register agent”; picker lists `agent:<id>` |
| Assign / reviewer | `AssignTicket` / edit | datalist of `human:owner`, session actor, registered `agent:<id>`; typed valid `human:` / `agent:` ids allowed |
| Move / review / complete | existing move / request-review / approve / complete | unchanged policy |
| Claim / release | `ClaimTicket` / `ReleaseTicket` | styled drawer actions; wrong-assignee claim is rejected |
| Comments / activity | `CommentTicket` + recent events | Activity tab |
| Dependencies | `LinkTickets` / `UnlinkTickets` (`blocks`, `blocked_by`, `parent`) | Policy tab |
| Schedule | existing set/clear | unchanged |
| Cancel | `move canceled` | stays in Canceled; not a delete |
| Delete | `DeleteTrackedTicket` | button is **Delete ticket** (not Archive). CLI `ticket delete` / `ticket archive` is the same ticket command: `canceled` + `archived=true`; markdown/events/history kept |

**Not in the ticket drawer:** runtime/evidence `tracker archive apply/restore`
(retention artifacts). There is **no restore-from-delete** and no purge.
`?archived=1` lists soft-deleted tickets only.

Revision digests still guard edits, moves, delete, links, claim, and bulk.
CSRF, session, loopback origin, and read-only gates are unchanged. No GET writes.

Saved board views from `tracker views save` are listed under Filters.

## What was actually exercised here

Real Home/Kanban against an Atlas-owned boards directory:

- create the board under that authorized root
- create a ticket
- register a custom Grok workspace profile
- edit assignee and reviewer
- wrong-assignee claim rejected
- explicit reassignment, then claim and release
- `ready` / `in_progress` / `request-review` and a comment persisted

Also verified: create in a selected existing directory (preview writes no workspace files; confirmation retains project values), attach an unregistered workspace, delete a ticket and find its retained history, and stale-edit conflict recovery. Desktop, tablet, and phone checks preserve the page width. A 120-ticket backlog remains readable and the last card is reachable. See [capture provenance](examples/browser-v1.16-captures.md).

## Capability inventory

### In the browser

- Home: workspace list, attention, search, safe settings, backup health, activity
- Create / attach a board under Atlas boards or discovery roots
- Review + confirm an existing absolute directory (Home-minted grant; exact path
  on the confirm form, no extra JS confirm)
- Optional paste of a CLI path grant (hidden while a preview is pending)
- Create project; open Kanban; schedule page
- Register workspace agent profiles; assign/review with pickers
- Ticket create, edit, labels, move, claim, release, review, comments, notes, links, schedule, cancel, Delete ticket
- Filters, saved board views, bulk move/assign/review/complete
- Read-only mode disables mutations and keeps data visible

### CLI-only (not copied for parity)

These stay terminal/MCP because they are admin, host, or high-impact:

- Editor MCP registration (`tracker init` / scoped `tracker setup`), `mcp serve`
- Skill/instruction refresh via `integrations install` (guidance, not MCP)
- Discovery-root widening (`atlas.settings.grant_discovery`)
- `workspaces grant` remains available; it is no longer required for a chosen existing directory in Home
- `doctor --repair`, reindex, git-mode host install
- Runtime/evidence `archive plan|apply|restore` (retention artifacts, not tickets)
- Backup remote targets, sync, import/export, uninstall, update
- Signatures, gates apply, permission profiles, security/redaction/audit packets
- Ticket heartbeat, protected/sensitive flags, views save/delete
- Bulk claim/release, TUI, team presets

## Design / state brief

**Job:** create a local board and move real tickets without leaving Home.

**Register:** product console (dense, calm, accountable). Signature move remains
the Kanban plus the Home create dialog — not a marketing hero.

**States**

| State | Behavior |
|---|---|
| Empty Home | Initialize board is the primary action |
| Empty project | New ticket + existing empty-column copy |
| Error | Exact service text, preserved fields, dialog/drawer stays open |
| Read-only | Controls disabled; overview and tickets remain readable |
| Loading | `is-busy` on submit (JS); no-JS posts normally |
| Destructive | Cancel ≠ Delete. Delete confirm names the ticket; records stay; no restore; no purge |
| Success | Redirect to workspace/project or ticket with flash |
| Long content | overflow-wrap on titles, paths, labels |
| Narrow | Home rail stacks; dialog `min(560px, 100vw-24px)`; board drawer already full-width on phones |
| Deleted | Hidden on the default board; listed when `archived=1` |

**Access:** visible focus, 44px controls at phone widths already in `app.css`,
native confirms, no color-only status, CSP self-only, no new UI dependency.

**Honesty:** no cookie banner, no analytics, no hosted agents, no autonomous
reviewer wakeups. Client MCP trust is file-based until the user restarts the
client.
